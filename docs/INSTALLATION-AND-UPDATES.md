# DeskZone 安装、升级与数据保留方案

## 目标

DeskZone 的程序可以被更新、替换或重新安装，但用户已经产生的数据必须保留。用户不应该因为安装新版本而丢失：

- 分类和分类顺序。
- 文件、文件夹和快捷方式引用。
- 最近打开记录。
- 面板位置、尺寸、折叠、锁定和外观设置。
- 本地操作记录。
- 数据库备份。

这是一条产品级约束，不依赖用户手动备份，也不能只依靠某个安装器的默认行为。

## 数据与程序必须分离

当前客户端的数据根目录是：

```text
%LOCALAPPDATA%\DeskZone\
```

程序文件位于安装目录，例如：

```text
C:\Program Files\DeskZone\
```

两者不能混用。安装器只能替换程序目录中的文件，不得把用户数据库或设置复制到安装目录，也不得在升级时清理数据根目录。

### 用户数据清单

```text
%LOCALAPPDATA%\DeskZone\
├─ deskzone.db              # 分类、项目引用、布局、操作记录
├─ deskzone.db-wal          # SQLite WAL 运行文件
├─ deskzone.db-shm          # SQLite 共享内存文件
├─ settings.json            # 外观和应用设置
├─ backups\                 # 数据库和设置备份
├─ logs\                    # 日志
└─ cache\                   # 可重建缓存
```

其中 `deskzone.db`、`settings.json` 和 `backups` 是升级保留的核心数据；`cache` 可以在明确需要时重建，但默认也不删除。

## 安装器规则

### 首次安装

1. 创建程序安装目录。
2. 写入 DeskZone 程序文件、依赖和快捷方式。
3. 不预创建或覆盖用户数据库。
4. 首次启动时由客户端创建 `%LOCALAPPDATA%\DeskZone` 和数据库。

### 升级安装

升级安装必须遵循以下顺序：

1. 检测并请求关闭正在运行的 DeskZone 进程。
2. 保留 `%LOCALAPPDATA%\DeskZone` 原样不动。
3. 替换程序安装目录中的旧版本文件。
4. 保留相同的安装产品标识和升级标识，使新版本被识别为升级而不是另一份独立安装。
5. 启动新版本。
6. 客户端启动时检查数据库版本，必要时先备份再执行迁移。

安装器禁止执行以下操作：

- 删除 `%LOCALAPPDATA%\DeskZone`。
- 删除 `deskzone.db`、`settings.json` 或 `backups`。
- 用空数据库覆盖已有数据库。
- 用默认设置覆盖已有 `settings.json`。
- 通过卸载旧版本来间接删除用户数据。

## 卸载策略

默认卸载只移除程序文件、快捷方式和安装器注册信息，保留用户数据。

如果未来需要提供“卸载并清除数据”，必须设计为单独的明确选项，并在执行前显示完整数据目录和不可恢复提示。普通升级流程绝不能触发该选项。

## 客户端启动与迁移策略

客户端启动时使用固定的数据根目录，不根据当前程序安装目录推导数据位置：

```text
DataPaths.RootDirectory
  = %LOCALAPPDATA%\DeskZone
```

启动流程：

1. 创建数据目录（目录已存在时不清空）。
2. 打开 SQLite 数据库。
3. 检查当前 Schema 版本。
4. 如果需要迁移，先创建一致性备份。
5. 在事务中执行迁移。
6. 执行数据库完整性检查。
7. 迁移成功后再显示主窗口。

如果数据库版本高于当前客户端支持的版本，应停止启动并提示用户安装更新版本，不能降级覆盖数据库。

## 版本兼容规则

- 程序版本和数据库 Schema 版本分开管理。
- 每次 Schema 迁移使用唯一迁移 ID。
- 迁移必须可重复检测，不能重复创建表或重复写入初始数据。
- 迁移失败时保留迁移前备份，不继续打开工作区。
- 新版本必须能够读取旧版本产生的数据。
- 降级不是默认支持的操作；如需降级，必须从备份恢复或提供明确的恢复流程。

## 备份与恢复

在数据库 Schema 升级前创建本地备份，备份至少包括：

- SQLite 一致性数据库副本。
- `settings.json` 副本。
- 备份创建时间和对应的程序 / Schema 版本。

建议保留最近 8 份备份。备份失败时不应继续执行破坏性迁移。

恢复时应：

1. 关闭 DeskZone。
2. 备份当前仍可读取的数据。
3. 从用户选定的备份恢复数据库和设置。
4. 重新启动并执行完整性检查。

## 推荐的发布流程

```text
构建 Release
    │
    ▼
生成安装包并签名
    │
    ▼
检测旧版本 / 保持相同升级标识
    │
    ▼
关闭旧进程
    │
    ▼
替换程序文件，不触碰 LocalAppData 数据
    │
    ▼
启动新版本
    │
    ▼
备份并执行数据库迁移
    │
    ▼
完整性检查后显示工作区
```

## 验收标准

每次安装器或数据库迁移改动都需要验证：

| 场景 | 预期结果 |
| --- | --- |
| 首次安装 | 创建程序和数据目录，首次启动成功 |
| 已有数据后覆盖安装 | 分类、引用、设置和最近打开记录保持不变 |
| 已有数据后升级 Schema | 自动备份，迁移成功，数据可读取 |
| 升级过程中客户端正在运行 | 安装器先处理旧进程，不产生数据库锁损坏 |
| 迁移失败 | 保留迁移前备份，不打开不完整工作区 |
| 普通卸载 | 程序移除，用户数据保留 |
| 重新安装 | 重新安装后自动读取原有数据 |
| 安装目录被删除后重新安装 | `%LOCALAPPDATA%\DeskZone` 中的数据仍可恢复 |
| 数据库版本高于客户端 | 提示安装更新版本，不覆盖数据库 |

## 当前项目状态

当前代码已经满足最重要的客户端边界：

- 数据根目录位于 `%LOCALAPPDATA%\DeskZone`，不在程序输出目录。
- SQLite 启动时执行 Schema Migration。
- Schema 升级前支持本地备份。
- 数据库版本过高时拒绝继续启动，避免降级破坏数据。

当前仓库已经提供可执行的用户级安装方案：

1. `installer/Publish-DeskZone.ps1` 负责生成独立发布目录。
2. `installer/Install-DeskZone.ps1` 负责首次安装、覆盖升级、验证和卸载。
3. 安装器默认使用 `%LOCALAPPDATA%\Programs\DeskZone`，用户数据使用 `%LOCALAPPDATA%\DeskZone`。
4. 升级前自动备份数据库、WAL、SHM 和设置文件。
5. 程序替换使用临时目录和旧版本回滚目录，替换失败时恢复旧程序。
6. 普通卸载只删除程序和快捷方式，明确保留用户数据。

发布脚本默认生成依赖 .NET 10 Runtime 的运行包；如果发布环境已经恢复对应的
`win-x64` Runtime 包，也可以传入 `-SelfContained true` 生成自包含包。无论采用哪种发布形式，用户数据目录都不在发布目录中。

正式发布前仍建议完成：

1. 为安装包签名。
2. 固定正式产品标识、升级标识和自动更新渠道。
3. 增加安装器自动化测试，覆盖首次安装、升级、卸载和迁移失败。
4. 如果提供“清除所有数据”，必须与普通卸载严格分离并要求明确确认。
